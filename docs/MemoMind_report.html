01 / PROBLEM

저연차 공무원의 조기 퇴직을 만드는 구조적 문제

체계적인 인수인계 없이 업무에 투입되고, 질문할 곳조차 없어 고립되는 저연차 공무원의 현실

📄
Pain Point

인수인계서 한 장만 전달받고 기피 업무에 배치되어 전임자의 기안문을 독학하는 3년 미만 저연차 공무원

합격의 기쁨도 잠시, 인사이동이나 면직으로 발생한 업무 공백을 떠안고 당장 쏟아지는 악성 민원과 행정업무를 충분한 준비 없이 혼자 감당해야 하는 사람.

관찰된 문제 구조

안정성에 대한 기대가 무너지고 조기 퇴직을 고민

  • 전임자의 부재로 체계적인 업무 인수인계가 이루어지지 않음
  • 수백 건의 과거 문서와 각종 지침을 스스로 찾아 해석해야 함
  • 조직 문화와 부족한 멘토링, 편하게 질문할 선배를 찾기 어려움
  • 업무 판단에 따른 법적·행정적 책임에 대한 부담이 저연차 공무원에게 집중됨
“인수인계서 한 장 받고 배치된 첫날, 질문할 사람도 없고 책임만 가득해 이미 퇴사를 결심했습니다.”
01 / VALIDATION

AI 기반 업무 인수인계 서비스 실효성 검증 프로젝트 추진 결과
"전임자에게 묻지 않아도 되는 구조"

저연차 공무원의 업무 공백과 인수인계 단절을 지방정부 AX 전환의 우선 과제로 정의하고,
AI를 활용해 업무지식을 구조화·검색·활용할 수 있는 서비스의 현장 적용 가능성과 실효성을 검증

종합 판정

AI 기반 인수인계 서비스의 핵심 기능 및 현장 적용 가능성 확인

  • 업무 메모의 등록·검색·수정·삭제부터 AI 기반 업무유형 분류, 자연어 질의응답, 근거 검색 및 답변까지 핵심 기능 구현, 서비스 실효성 검증함.
  • 96건의 실제 업무 데이터와 17개 업무유형을 대상으로 온디바이스 경량 AI 모델을 활용해 기존 업무자료를 구조화하고 필요한 정보를 자연어로 검색·확인할 수 있음을 확인함.
  • 전임자의 경험과 문서에 흩어진 업무지식을 후임자가 재활용할 수 있는 AI 기반 업무지식 자산화 및 인수인계 지원 모델의 가능성을 확인함
  • 부서·업무그룹 단위의 공동 활용을 위한 서버형 데이터베이스와 권한관리, 실제 지방정부 업무환경에서의 효과성 검증이 필요함.

02-1 / USER GUIDE

MemoMind 메모관리 및 인수인계 방법

업무 메모를 등록·수정하고, 필요한 메모를 추출하여 후임자에게 전달하는 기본 사용 방법입니다.

GUIDE 01 · 메모관리

메모 등록 및 수정 방법

프로젝트별 업무 내용을 등록하고, 저장된 메모를 최신 내용으로 수정합니다.

업무 메모관리로 이동메인 화면에서 ‘업무 메모관리’ 메뉴를 선택합니다.
프로젝트명 입력메모를 구분할 수 있도록 해당 업무의 프로젝트명을 입력합니다.
내용 입력 후 등록·수정업무 내용을 입력해 등록하거나, 기존 메모를 선택해 내용을 수정합니다.
메모 등록·수정 GIF 자리docs/images/MemoMind_memo_register_edit.gif
GUIDE 02 · 인수인계

메모 인수인계 방법

전체 또는 필요한 단위 메모만 추출하고, 전달받은 메모를 등록합니다.

인수인계 버튼 선택업무 화면에서 ‘인수인계’ 버튼을 선택합니다.
전체 또는 단위 메모 추출해당 메모 전체 또는 필요한 단위 메모를 선택해 파일로 추출합니다.
전달받은 메모 입력후임자는 전달받은 해당 메모 파일을 선택해 MemoMind에 입력합니다.

03-1 / ARCHITECTURE

지방정부 AX(인공지능 전환)를 위한 GPU 활용 실증 결과

대규모 예산을 투입하여 고가의 새 서버를 도입하지 않더라도, 보유 서버 재정비하는 것만으로 AX 전환이 가능함을 증명했습니다. 기존 HP 서버에 단 8백만 원 수준의 저전력 T4 GPU 자원을 증설 및 최적화하여, 하드웨어 하향 평준화 환경에서도 중단 없는 고품질 RAG형 에이전트 서비스를 성공적으로 실증하였습니다.

01
T4 GPU 1대당 전력 소모량 대기(Idle) 상태 시 33W 소모, AI 추론 구동 시 66W 소모로 초저전력 환경 입증
02
66W 소비전력 시사점노란색 백열전구 단 1개 수준의 전력만으로 지방정부나 중소기업도 비용 부담 없이 도입 가능한 초경량·고효율 아키텍처 실증
03
[문제점] 멀티 GPU 모델 분산 구동 시 단일 모델의 레이어 분산 운영으로 인한 추론 속도 저하 및 함수 호출(Function Calling) 먹통 현상 발생
04
[조치사항] GPU별 독립 모델 인스턴스 할당 GPU 1대당 1개의 초경량 모델을 개별 로딩하여 최상의 추론 속도 확보 및 핵심 함수 호출(Function Calling) 기능 완벽 구현
05
4개 GPU 자원 분산 처리LLM의 연속 토큰 생성 특성상 전통적 로드밸런싱의 한계를, 무작위 세션 배분(Random Allocation) 알고리즘으로 해결
06
Nginx 무작위 라우팅 실증Nginx의 Random 분배 설정을 적용하여, 행정 현장의 실무자 동시 접속 20명 수준의 병렬 요청을 안정적으로 동시 처리
GPU 01 · 자원 산정

업무 유형별 최적의 GPU 수준 산정

문서 요약·민원 분류 등 경량 업무와 영상·음성 분석 등 고연산 업무를 명확히 구분함.

방향: 업무량·동시 사용자·모델 기준의 설계로 GPU 과잉 투자 방지
GPU 02 · 효율 운영

공용 GPU 풀 기반의 유연한 자원 배분

부서별 개별 도입으로 인한 중복 투자를 막고 피크 시간대 병목 현상을 해소함.

방향: 유휴 GPU 최소화를 위해 새벽 시간 배치처리 등 적용
GPU 03 · 개인 AX 확산

자체 운영 AI 모델 API 활용 문화 확산

자체 GPU 인프라를 API 형태로 개방하여, 직원이 개인 업무에 AI를 손쉽게 접목하도록 지원

방향: 범기관 API 허브 제공으로 부서별 개별 구축을 방지하고 상향식(Bottom-up) AX 문화 조성
04 / EVIDENCE

AI 인수인계 MemoMind 서비스 실효성 검증

구현 여부를 넘어 실제 업무지식이 구조화되고, 필요한 정보를 찾고, 후임자에게 전달될 수 있는지를 단계별로 검증

  • 기존 업무 메모를 프로젝트·업무유형·내용 등의 구조화된 데이터로 관리할 수 있도록 구현함.
  • 96건의 실제 업무 데이터와 17개 업무유형을 기준으로 업무지식을 구조화하고 관리할 수 있음을 확인함.
  • 업무별 JSON 추출을 통해 특정 업무지식을 별도 단위로 저장하고 후임자에게 전달할 수 있는 구조를 확인함.
근거: 실제 업무 DB 96건·17개 업무유형 · 업무별 JSON 추출 파일 · MemoMindAI.py 데이터 처리 로직
  • 사용자의 자연어 질문을 AI가 기존 업무유형과 연결하고 관련 업무자료를 검색하는 흐름을 구현함.
  • AI 분류 이후 DB의 정확 일치 검색을 적용해 불필요한 검색 복잡도를 줄임.
  • 목록 밖 업무유형이나 낮은 신뢰도의 경우 억지로 기존 업무에 매칭하지 않고 일반답변으로 처리하도록 설계함.
근거: MemoMindAI.py AI 분류·검색 로직 · 업무유형 캐시 · 신뢰도 기반 분기 처리
  • 기존 문서와 업무 메모를 기반으로 후임자가 자연어 질문을 통해 필요한 업무정보를 확인할 수 있는 구조를 구현함.
  • 업무별 근거와 메모를 함께 제공해 단순 AI 생성답변이 아닌 기존 업무자료 기반의 답변이 가능하도록 구성함.
  • 실제 신규·저연차 공무원이 기존 인수인계 방식보다 업무 파악 시간을 단축하는지는 현장 사용자 테스트가 필요함.
근거: AI 질의응답·근거 검색 기능 · 업무 메모 데이터 · 현장 사용자 테스트 추가 필요
  • 핵심 사용 흐름을 업무자료 등록 → 자연어 질문 → 답변 확인의 단순한 구조로 구성함.
  • 모델 및 AI 서버 설정은 사용자 화면에서 숨겨 일반 사용자가 AI 기술을 직접 이해할 필요가 없도록 설계함.
  • 중복 전송 방지, 진행 메시지, 오류 안내, 수정·삭제 기능 등을 구현해 실제 업무환경에서의 사용 편의성을 고려함.
  • 실제 공무원의 최초 사용 완료시간과 교육 필요 여부는 사용자 관찰 테스트를 통해 추가 검증할 필요가 있음.
근거: MemoMindAI.py UI·입력·오류 처리 로직 · 서비스 소개 화면 · 사용자 테스트 추가 필요
  • AI가 모든 질문을 임의로 업무유형에 매칭하지 않도록 신뢰도 기준과 목록 외 처리 로직을 적용함.
  • 업무자료의 수정·삭제 기능과 JSON 중복 등록 방지를 통해 데이터 관리 오류를 줄이도록 구성함.
  • AI 서버 연결 실패 시 오류를 사용자에게 안내하도록 구성함.
  • 지방정부 확대 적용을 위해서는 개인정보·행정정보 보호, 권한관리, 업무자료 최신성 관리 및 AI 답변 검증체계에 대한 추가 검토가 필요함.
근거: MemoMindAI.py 오류처리·신뢰도 분기·데이터 관리 로직 · 기관 단위 운영 시 보안·권한관리 추가 검증 필요
  • 현재 개인 단위 업무지식 관리 구조를 기반으로 부서·업무그룹 단위의 공동 활용 모델로 확장할 수 있음.
  • 향후 서버형 데이터베이스를 적용하면 부서별 업무지식의 축적과 공동 활용이 가능함.
  • 부서·직급·업무별 접근권한을 적용해 기관 내 업무지식 공유 범위를 관리할 필요가 있음.
